# 포근동행 v2 — 중앙 제작·배포, 기관 검토·매칭·운영

2026-11-01. 사용자가 정한 운영 모델을 반영한 최신 설계입니다. **매칭은 각 기관에서 검토하고 진행합니다.**

[디자인 검토 보드](index.html)에서 학생·튜터·기관·중앙 운영자의 UI 시안 4장(8개 화면 예시), 역할별 IA·내비게이션·화면흐름도 12개, 전체 운영 연결도 1개를 볼 수 있습니다. 기존 v1은 비교용으로 보존합니다. 본 v2의 역할·권한 정의가 v1의 튜터 자료 제작 및 중앙 매칭 확정 제안을 대체합니다.

## 확정한 역할 분담

| 역할 | 담당 업무 | 핵심 화면 |
|---|---|---|
| 중앙 운영자 | 교육과정 기반 공통 학습자료 제작·내부 검토·배포·버전 관리, 전국 기관 운영 현황 확인·지원 | 전국 현황, 기관 관리, 자료 제작, 자료 배포, 운영 지원 |
| 기관 | 소속 튜터·학생의 조건 검토, 매칭 확정·변경·재배정, 일정·출결·수업 운영, 중앙 자료 수신·클래스 연결 | 운영 홈, 참여 학생, 튜터·매칭, 일정·자료, 지원 |
| 대학생 튜터 | 중앙 배포 자료로 수업 준비·진행, 복습 배정, 질문 답변·보충, 오류·개선 의견 전달 | 오늘, 클래스, 배포 자료, 질문함, 학습 기록 |
| 학생 | 배정된 수업 참여, 동일 자료 기반 복습, 질문·답변 확인·재시도 | 오늘, 배움방, 질문 |

**중앙은 기관별 매칭 현황을 조회하고 운영을 지원합니다. 매칭의 검토·승인·확정·변경·재배정 담당자는 해당 기관입니다.** 튜터가 자료를 작성해 중앙 승인을 받는 절차는 제거했습니다. 중앙 내부에서는 제작과 품질 검토 책임을 나누는 안을 제안합니다. 인력 배치 방식은 추후 정할 수 있습니다.

## 서비스의 세 흐름

1. **자료:** 중앙 제작 → 중앙 내부 검토 → 기관 배포 → 기관 수신·클래스 연결 → 튜터 수업 → 학생 복습·질문.
2. **매칭:** 기관 참여 확인 → 튜터 자격·과목·시간·정원 검토 → 기관 매칭 확정 → 클래스·일정 안내 → 기관에서 변경·재배정 관리.
3. **운영 관리:** 기관 운영 현황 공유 → 중앙에서 전국·지역·기관별 현황 확인 → 기관과 문제 사유 확인 → 담당·기한을 정해 지원 → 기관 조치·중앙 재확인.

## 기관의 매칭 검토·진행

I04에서 참여 학생과 튜터를 선택하고, 기관 담당자가 튜터 자격 확인 상태·학생 참여 및 동의 확인 상태·과목·가능 시간·정원·수업 장소를 검토합니다. 조건이 맞지 않으면 후보·시간을 조정하거나 대기 사유와 다음 안내일을 기록합니다. 조건을 충족한 경우 기관 담당자가 **매칭 확정하기**를 실행하는 설계입니다.

확정 후 클래스·일정·담당 관계를 만들고 학생·튜터에게 안내합니다. 튜터 중단이나 시간 변경도 기관에서 대체 후보 검토·재배정·보강·인계로 처리합니다. 중앙의 사전 승인 단계는 없습니다. 중앙에 운영 지원을 요청해도 매칭 확정 책임은 기관에 둡니다.

## 중앙의 전국 운영 현황

| 확인 영역 | 지표·상태 제안 | 다음 행동 |
|---|---|---|
| 기관 운영 | 운영 기관 수, 보고 시점, 미보고 기관 | 기관 상세·담당자 확인 |
| 매칭 | 기관별 미배정 학생·클래스, 대기 사유·기간 | 기관이 검토·진행할 수 있도록 사유 확인·지원 |
| 수업 | 예정·진행·취소·보강 일정, 수업 공백 | 기관 운영 기록 확인·지원 등록 |
| 자료 | 배포 대상, 전달 결과, 기관 수신, 클래스 사용 버전 | 미수신 확인·재전달·적용 지원 |
| 학습 지원 | 배정된 복습의 제출 상태, 기한을 넘긴 미답변 질문 | 기관·튜터 지원 필요 확인 |
| 운영 지원 | 미처리 요청, 담당, 기한, 조치·재확인 상태 | 담당 지정·기한 협의·후속 확인 |

전국 현황의 카드에서 지역·기관 상세로 내려가 실제 사유와 조치 내역을 확인합니다. 단순 순위보다 지원이 필요한 기관을 찾는 데 집중합니다. 집계 기간·분모·최종 보고 시점을 함께 표시하고, **미보고는 0이나 정상으로 처리하지 않습니다.** 구체적인 지연 기준·답변 기한·집계 주기는 운영 정책으로 정할 항목입니다. 시안의 인원·기관명·수치는 예시입니다.

수업 진행률·복습 완료·학생의 이해 자기 확인은 서로 다른 상태입니다. 자료 **배포**, 기관 **수신**, 클래스 **사용**도 구분합니다. 대시보드 숫자만으로 실제 프로그램 품질이나 학생 성취를 단정하지 않습니다.

## 중앙 자료 제작·배포

중앙 운영자가 학년·과목·단원과 교육과정·공식 성취기준을 선택합니다. AI 초안 만들기 또는 직접 편집으로 **학생 자료·튜터 지도안·복습 문제와 정답·해설**을 함께 만듭니다. 내부 검토에서 내용·정답·해설·학년 적합성과 교육과정 연결을 확인한 뒤 배포 가능한 버전으로 확정합니다.

배포 시 기관 범위·과목·대상 차시·적용 시점을 지정하고 변경점을 안내합니다. 기관은 수신을 확인해 클래스에 연결하고 튜터는 해당 버전으로 수업합니다. 기관별 진도는 달라도 같은 차시에서는 동일하게 관리된 자료를 사용하는 구조입니다.

오류 신고는 튜터·기관에서 중앙으로 전달합니다. 중앙은 영향 범위를 확인하고 필요하면 배포 중지·수정·내부 재검토·새 버전 배포를 진행합니다. 이미 진행한 수업·복습·질문의 참조 버전은 보존하고 변경 이력을 남깁니다. 기관과 튜터는 원본을 덮어쓰지 않고 수업 메모·보충 설명을 별도로 기록합니다.
