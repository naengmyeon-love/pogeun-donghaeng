확인일: 2026-11-03. 기준: `포근동행/공개배포/site/dist`의 실제 app.js/engine.js, 최신 `프로토타입/README.md`. 공개 배포 버전 2의 기능과 로컬 배포 소스를 기준으로 확인했다. 초기 와이어프레임 및 output 폴더는 기준으로 사용하지 않았다.

## 발표에서 설명할 서비스

초등 5학년 수학·영어의 지역 학습지원 서비스. 학생–대학생 튜터의 연결과 함께 공통 자료, 수업, 복습, 문항 질문, 운영 지원을 하나의 흐름으로 묶는다. 운영 책임은 **중앙 제작·배포 / 기관 검토·매칭·운영 / 튜터 수업·답변 / 학생 복습·질문**으로 나뉜다.

핵심 문장: “매칭으로 시작한 배움을, 다음 수업까지 이어 줍니다.”

## 역할별 실제 구현 흐름

### 학생

1. 학생·보호자 가입 시 기관·희망 과목·가능/선호 시간·학습 목표·지도 방식·수준 등을 입력한다. 가입 없는 예시 체험도 가능하다.
2. 기관이 확정한 배움방과 다음 수업의 튜터·시간·학습실을 확인한다.
3. 수업에 연결된 같은 자료를 열어 개념과 예제를 보고 복습한다.
4. 선택형 문제에서 오답 힌트·재시도·정답 해설을 확인한다.
5. 막힌 문항에서 질문을 남긴다. 질문은 자료 버전·문항·클래스 문맥을 유지한다.
6. 튜터 답변을 확인하고 “이해했어요” 또는 재질문을 선택한다. 학습 기록을 볼 수 있다.
7. 별도로 학기 자료에서 5문제씩 독립 연습할 수 있다. 독립 연습은 클래스 복습과 구분된다.

### 튜터

1. 가입/내 정보·서류에서 활동 정보와 검토용 범죄경력조회서 파일을 첨부한다. 기관의 검토 결과(확인 완료/보완 요청)를 기다린다.
2. 기관이 배정한 클래스를 확인한다. 중앙에서 배포된 학생 자료·튜터 지도안·복습 문제를 함께 열어 준비한다.
3. 수업 시작 → 출석 확인 → 수업 메모 → 수업 완료·복습 배정으로 진행한다.
4. 담당 학생 질문에서 원래 문항과 학생 설명을 함께 보고 답변한다. 답변 도착과 학생 이해 확인은 다른 상태다.
5. 자료 오류·개선 의견을 중앙에 전달한다.

### 기관

1. 소속 학생의 참여 상태와 튜터 자격·서류를 확인하고, 가능 시간 등 매칭 정보를 보완한다.
2. “자동매칭안 만들기”로 과목별 최대 3명의 후보를 검토한다. **추천만으로 클래스는 생성되지 않는다.**
3. 학생·튜터 의사와 활동 기간/목표를 확인하고 **기관 최종 승인**한다. 필수조건(과목, 자격/서류, 참여, 시간, 정원, 장소 충돌)을 승인 시 다시 검사한다. 반려 사유를 기록할 수 있다.
4. 직접 구성·기존 클래스 변경은 1~4명 그룹을 지원한다. 자동추천은 학생별 1명 안이다.
5. 중앙 자료를 수신 확인한 뒤 예정 클래스에 연결한다.
6. 일정 취소·보강 확인, 복습 기기 등 지원 요청과 조치 내용을 관리한다.
7. 중앙의 별도 매칭 승인 단계는 없다.

### 중앙기관(화면 명칭: 중앙 운영자)

1. 교재 에이전트에서 5학년 수학/영어의 단원·참고 차시·목표·수업 시간·수준·문항 수를 선택해 학생 교재·복습 문제·지도안을 자동 구성한다. 학생 교재·지도안·검토 결과를 한 화면에서 확인하고, 문항·선택지·정답·힌트·해설도 편집한다. 수학 7차시는 수치 변형 문항을 생성·검산하며 나머지는 원본문항 은행을 활용한다. 수록 자료 기반으로 작동하고 외부 생성형 AI를 호출하지 않는다.
2. 생성 후 자동 점검·안전 수정 → 내부 검토 → 배포 준비 → 기관 배포로 진행한다. 오류가 남으면 검토·배포를 막으며 자동 점검이 사람의 승인을 대신하지 않는다. 4개 체크항목은 교육과정 근거, 내용/정답/해설, 학년 수준/표현, 자료·지도안·복습의 일치다.
3. 기관별 수신과 클래스 사용을 구분해 확인한다.
4. 배포 원본을 직접 바꾸지 않고 새 버전을 만든다. 진행/완료 수업의 자료와 이전 질문의 버전은 보존한다.
5. 전국·지역별 기관 현황과 운영 지원을 본다. 이 현황은 실제 전국 데이터가 아닌 예시다.

## 실제 코드 기준의 설명 가능한 차별점

- 연결 이후의 운영까지: 매칭 → 공통자료 → 수업 → 복습 → 문항질문 → 답변 → 이해 확인 → 다음 수업 보충.
- 중앙의 공통 제작·버전 관리와 지역 기관의 배정·일정·지원 책임 분리.
- 문항 질문에 당시 자료 버전과 문제 문맥이 남아 튜터가 같은 문제를 보고 답한다.
- 자동추천과 사람의 최종 승인을 분리하고 조건을 재검사한다.
- 자료를 “배포했음 / 기관이 수신했음 / 실제 클래스에 연결했음”으로 나눠 본다.
- 단, 타 프로그램에 해당 기능이 없다고 단정할 근거는 본 감사에 없다. 외부 프로그램 비교에는 “포근동행이 제안하는 운영 범위”로 표현한다.

## 구현·예시·후속 구현 구분

**시연 가능**: 브라우저 가입/로그인, 역할별 화면, 추천·기관 승인, 파일 첨부/기관 검토, 교재 자동 구성·점검·안전 수정, 자료·문항 편집·검토·배포·수신·클래스 연결, 수업·출석·복습·질문·답변·이해/재질문, 기록·지원 상태.

**준비된 예시**: 모든 이름/기관/전국 현황/운영 기록, 기존 고정 예시 초안(새 교재 에이전트는 수록 자료 기반 실제 자동 구성, 외부 AI API 호출 없음), 자료의 검토·배포 상태(실제 교사 검수나 교육부 인증 아님), 초기 추천 배점(성공 확률이나 검증된 교육효과 아님).

**후속 연결 필요**: 서버 인증과 운영 권한, 비공개 서버 저장, 여러 기기/사용자 간 동기화, 실제 알림 발송, 실제 AI 생성과 성취기준 자동검증, 실제 기관 등록/동의/서류 관리, 반복 일정, 화상수업, 영어 음원·발음 분석.

교육자료: 과목별 18주, 주 1회 40분의 보충학습 예시. 수학 18차시 + 영어 18차시, 각 5문항 총 180문항. 정규 교과 전체 시수 대체를 뜻하지 않는다. 영어 듣기는 튜터가 대본을 읽는 방식이고 선택형 점수는 듣기/말하기 숙달 지표가 아니다.

발표에는 “가상 데이터 기반 브라우저 저장형 프로토타입 · 교재는 수록 자료 기반 자동 구성 · 외부 생성형 AI 미연결”이라고 표시한다. 학습효과·시간 절감은 실측하지 않았으므로 외부 근거·가정에 따른 시나리오로만 설명한다.

## 발표에 적합한 90초~2분 연결 시연

1. 첫 화면 → “가입 없이 예시 화면 체험하기” 펼침 → 학생. 필요하면 상단 초기화.
2. 이지우 학생의 수학 복습 → “여기서 막혔어요” → 문항 질문 입력.
3. 상단 튜터 → 김민서 → 질문함 → 새 질문 답변.
4. 상단 학생 → 답변 확인 → 이해했어요.
5. 남은 시간에 기관의 자동매칭 승인 또는 중앙 자료 제작/배포 화면을 정적으로 소개.

생방송 시연은 이 단일 학습 연결만 수행하고, 4개 역할 전체 운영은 발표의 화면 이미지와 흐름도로 설명하는 편이 15분 내 안정적이다. 한 브라우저에서 역할을 전환해야 기록이 이어진다. 관객 휴대폰과 발표 노트북은 동기화되지 않는다.

체험 QR은 `포근동행/공개배포/포근동행-체험-QR.png` 또는 svg를 그대로 재사용 가능하다.
