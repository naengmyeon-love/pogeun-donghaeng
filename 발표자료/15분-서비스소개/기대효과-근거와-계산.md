# 기대효과: 근거와 계산

확인일: 2026-11-03. 발표 본편은 **21장·15분**, 참고 부록은 5장입니다. 이 문서는 기능 규모, 외부 연구 결과, 운영 시나리오를 구분하기 위한 발표 보충자료입니다. **포근동행의 학습효과나 운영시간 절감은 아직 실측하지 않았습니다.**

## 1. 숫자의 성격

| 구분 | 발표에 사용할 숫자 | 정확한 의미 |
| --- | --- | --- |
| 구현된 기능 규모 | 수학 18차시 + 영어 18차시 = 36차시, 원본 복습 180문항 | 현재 수록된 보충학습 자료의 양. 실제 참여자 수·운영 실적·성취 향상이 아님 |
| 구현된 기능 범위 | 20·40·60분, 복습 3·5·8문항, 기초·기본·도전 | 선택 가능한 자동 구성 조건. 모든 교육적 적합성이 자동 검증된다는 의미가 아님 |
| 구현된 생성 범위 | 수학 7차시의 수치 변형·검산 | 수학 1~6차시 및 11차시(통분). 나머지는 원본문항 은행을 활용하며 필요한 경우 같은 단원의 다른 차시를 포함함 |
| 기능 검증 기록 | 자동 테스트 37개 통과 | 생성·편집·검수·승인·배포·학습 연결의 코드 검증. 실제 교사 검수나 교육효과 인증이 아님 |
| 외부 연구 | 튜터링 평균 0.288 표준편차, EEF 소집단 지도 +4개월 | 서로 다른 외부 연구·요약의 결과. 포근동행의 효과 예측값이 아님 |
| 운영 시나리오 | 공통 원고 제작 건수 90% 감소, 중앙 작업시간 25% 감소 | 아래 조건을 가정한 계산. 현장 실측 결과가 아님 |

교재 에이전트는 **수록 자료 기반 자동 구성**입니다. 외부 생성형 AI를 호출하지 않습니다. 자동 점검 뒤에도 교육과정 근거·내용·정답·해설·학년 적합성의 중앙 검토와 승인이 필요합니다. 근거는 [프로토타입 안내](../../프로토타입/README.md), [검증 기록](../../프로토타입/QA.md), [공개 배포 안내](../../공개배포/README.md)입니다.

## 2. 외부 연구는 설계의 근거로 사용

| 출처 | 확인한 결과·조건 | 발표에서의 해석 |
| --- | --- | --- |
| Nickow·Oreopoulos·Quan, *American Educational Research Journal* (2024) | 튜터링 실험 연구 메타분석의 통합 효과 0.288 표준편차 | 구조화된 튜터링을 검토할 근거. 포근동행 학생의 예상 점수나 향상률로 적용하지 않음 |
| EEF, *Small group tuition* | 평균 +4개월, 근거 연구 62개. 보통 2~5명 소집단이며 주 3회 안팎의 빈번한 운영 등 실행 조건을 함께 설명 | 포근동행의 현재 주 1회·40분 보충학습과 운영 강도가 다름. 동일한 +4개월을 기대한다고 말하지 않음 |

학술 출처: [AERJ 논문, DOI 10.3102/00028312231208687](https://journals.sagepub.com/doi/10.3102/00028312231208687), [ERIC 공식 서지·초록](https://eric.ed.gov/?id=EJ1406037). EEF 출처: [Teaching and Learning Toolkit — Small group tuition](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/small-group-tuition). 확인일 2026-11-03. EEF 페이지가 표시한 근거 검토 갱신 시점은 2021년 7월이며 근거 강도는 중간입니다.

**0.288 표준편차를 28.8% 향상으로 바꾸지 않습니다.** 표준편차와 학습 개월은 서로 다른 척도이므로 합산하지 않습니다. +4개월은 모든 학생에게 보장되는 기간이나 학습 시간을 4개월 줄인다는 뜻도 아닙니다. 외부 결과를 포근동행의 교육효과 실측처럼 표시하지 않습니다.

## 3. 시나리오 A: 같은 공통 원고의 중복 제작

**가정:** 10개 기관이 같은 학년·2과목·18차시를 사용하며, 기관마다 동일 범위의 공통 원고를 각각 새로 제작한다고 놓습니다. 공통 원고 한 꾸러미는 학생 교재·복습 문제·튜터 지도안의 세트를 뜻합니다.

| 비교 | 계산 | 공통 원고 제작 건수 |
| --- | --- | ---: |
| 기관별 독립 제작 | 10기관 × 2과목 × 18차시 | 360건 |
| 중앙 공통 제작·공유 | 2과목 × 18차시 | 36건 |
| 차이 | (360 − 36) ÷ 360 × 100 | **90%** |

이 수치는 **공통 원고를 중앙에서 한 번 만들고 재사용하는 구조의 이론적 차이**입니다. 이번 에이전트만의 추가 효과가 아닙니다. 기관별 준비·현장 확인·학생별 조정·수업 운영·배포 후 재검토까지 90% 줄었다는 뜻이 아닙니다. 실제 기관이 이미 공유 교재를 쓰고 있다면 이 비교의 출발 가정은 성립하지 않을 수 있습니다.

발표 문장: “10개 기관이 동일한 36차시의 공통 원고를 각각 새로 만드는 상황을 가정하면, 중앙 공통 제작으로 원고 제작 건수를 360건에서 36건으로 줄일 수 있습니다. 현장 적용 준비는 계속 필요합니다.”

## 4. 시나리오 B: 에이전트의 중앙 작업시간 차이

**가정:** 동일한 원본을 바탕으로 36꾸러미를 구성합니다. 중앙의 꾸러미당 구성·편집은 30분에서 15분으로 줄고, 사람의 내용 검토는 전후 모두 30분으로 유지한다고 놓습니다. 이는 실제 측정된 평균이나 모든 교재의 권장 제작시간이 아닙니다. 완전히 새로운 단원·원고를 처음부터 집필하는 시간을 뜻하지 않습니다.

| 중앙 업무 | 수동 구성 | 에이전트 활용 가정 |
| --- | ---: | ---: |
| 꾸러미당 구성·편집 | 30분 | 15분 |
| 꾸러미당 사람 검토 | 30분 | 30분 |
| 꾸러미당 합계 | 60분 | 45분 |
| 36꾸러미 총계 | 36 × 60 ÷ 60 = **36시간** | 36 × 45 ÷ 60 = **27시간** |

차이는 **9시간**, 중앙 구성·검토 업무를 분모로 하면 `(36 − 27) ÷ 36 = 25%`입니다. **25%는 중앙 업무에만 해당하는 가정상 차이**입니다. 앞의 원고 건수 90%와 더하거나 곱해 전체 운영효과로 환산하지 않습니다.

발표 문장: “한 꾸러미의 구성·편집을 15분 줄이고 사람 검토 30분을 유지한다고 가정하면, 중앙의 36꾸러미 제작·검토는 36시간에서 27시간이 됩니다. 25%는 이 중앙 업무만의 시나리오이며 파일럿에서 검증하겠습니다.”

### 기관의 현장 적용을 포함한 분모

기관별 현장 확인·수업 연결에 꾸러미당 20분이 들고 전후 같다고 가정하면 `10 × 36 × 20 ÷ 60 = 120시간`입니다.

| 비교 범위 | 수동 구성 | 에이전트 활용 가정 | 차이 |
| --- | ---: | ---: | ---: |
| 중앙 구성·검토만 | 36시간 | 27시간 | 9시간·25.0% |
| 중앙 + 10기관 현장 적용 | 36 + 120 = 156시간 | 27 + 120 = 147시간 | 9시간·약 **5.8%** |

따라서 “전체 운영시간 25% 절감”으로 표현하면 분모가 바뀝니다. 위 156시간도 아래의 제외 업무를 포함하는 전체 운영비용은 아닙니다.

### 구성·편집시간 가정에 따른 민감도

사람 검토는 모두 30분으로 고정합니다. 비교 기준은 중앙의 수동 구성·검토 36시간입니다.

| 활용 후 구성·편집 | 꾸러미당 총시간 | 중앙 36꾸러미 | 중앙 시간 차이 |
| --- | ---: | ---: | ---: |
| 25분 | 55분 | 33시간 | 3시간·8.3% |
| 15분 | 45분 | 27시간 | 9시간·25.0% |
| 10분 | 40분 | 24시간 | 12시간·33.3% |

작업시간은 모두 가정입니다. 개발·서버 운영, 튜터 수업, 학생 질문 답변, 예외적 수정·재제작, 교육과정 갱신, 추가 전문가 검증·교육·현장 품질확보 비용은 계산에서 제외했습니다. 표의 정규 내용 검토 30분은 포함했지만 그것만으로 필요한 모든 품질확보 비용을 대표하지 않습니다. 실제 예외 처리나 검토 부담이 커지면 절감이 없거나 작업시간이 늘 수도 있습니다.

## 5. 파일럿에서 가정을 실측으로 바꾸는 방법

| 지표 | 측정 정의·분모 | 해석할 때의 주의점 |
| --- | --- | --- |
| 중앙 구성·편집시간 | 꾸러미별 사람의 작업 타이머. 조건 입력·자료 선택·편집을 포함 | 검토시간과 분리 기록. 브라우저의 순간 생성시간을 사람의 총업무시간으로 대신하지 않음 |
| 중앙 검토시간 | 같은 꾸러미의 교육내용·정답·해설·표현·근거 확인 타이머 | 구성과 중복 집계하지 않음. 작업자 수가 여럿이면 인시를 합산하고 경과시간은 별도 기록 |
| 기관 현장 적용시간 | 기관·꾸러미별 진도·수준 확인, 현장 조정, 클래스 연결의 사람 작업시간 | 중앙에서 줄인 시간과 별개. 튜터의 실제 수업 준비시간도 별도 기록 |
| 재작업률 | 최초 검토에서 수정 요청을 받은 꾸러미 수 ÷ 최초 검토한 꾸러미 수 | 재검토 횟수를 새 꾸러미로 중복 집계하지 않음. 사소한 수정과 내용 오류를 구분 |
| 7일 복습 완료율 | 배정 후 7일의 관찰기간을 확보한 학생–차시 배정건 중, 7일 안에 배정 5문항 모두 제출한 건수 ÷ 해당 배정건수 | 파일럿 공통 과제는 5문항으로 고정. 최근 배정으로 7일이 안 지난 건은 분모에서 제외. 완료와 정답률은 별도 지표 |
| 48시간 첫 답변율 | 생성 후 48시간의 관찰기간을 확보한 신규 질문 중, 생성 후 48시간 안에 담당 튜터의 첫 답변이 기록된 질문 수 ÷ 해당 신규 질문 수 | 재질문 스레드를 새 질문으로 중복 집계하지 않음. 답변 등록은 학생의 열람·이해 완료가 아님. 열람시간은 현재 미수집 |
| 학습 변화 | 같은 학습범위의 사전·사후 평가. 가능하면 동등 난이도의 다른 문항 사용 | 반복 노출·중도 이탈·결측을 기록. 비교집단이 가능하면 두 집단 변화량의 차이를 보고 표본 수와 불확실성을 함께 제시 |

시간은 작업 구간의 정의를 먼저 맞춘 뒤 중앙값·분포·표본 수를 함께 보고합니다. 시나리오의 30분·15분·20분은 그 결과로 교체합니다. 작은 파일럿의 전후 변화나 학생의 “이해했어요” 표시만으로 플랫폼의 인과적 교육효과를 확정하지 않습니다.

**발표 공통 표기:** “기능 규모는 구현 확인, 학습 근거는 외부 연구, 운영효율은 가정 기반 시나리오입니다. 포근동행의 현장 효과는 파일럿에서 검증합니다.”

## 6. 개선 발표의 추가 업무시간 가정

본편 17번은 중앙 제작·검토와 튜터 준비·기록을 비교하고, 18번은 지역 멘토링 기여를 설명합니다. 외부 연구는 부록 R5에서 설명합니다. 중앙 업무만의 25%와 기관 적용 포함 5.8%는 부록 R2에서 구분합니다.

아래 값은 현장 조사·공식 공지의 업무시간 평균이 아니며 신규 파일럿에서 검증할 조건부 예시입니다.

| 업무 | 수동 → 활용 후 가정 | 적용량 가정 | 시간 차이 |
|---|---|---|---|
| 튜터 수업 준비 | 회당 25분 → 15분 | 주당 20개 수업 × 18주 = 360회 | 60시간, 해당 업무 40% |
| 출석·수업·복습 기록 | 회당 10분 → 6분 | 360회 | 24시간, 해당 업무 40% |
| 최초 배정 검토 | 학생–과목 배정당 30분 → 20분 | 20건 | 3시간 20분, 해당 업무 약 33% |
| 질문 문맥 확인 | 질문당 5분 → 3분 | 질문 180건 | 6시간, 해당 업무 40% |

- 수업 준비는 자료 탐색·문항 선정·지도안 정리 등을 비교하며 학생별 진도·수준 확인은 계속 필요합니다.
- 기록 시간은 기존에 여러 곳에 중복 입력하는 현장을 전제합니다. 공식 양식 재입력이 남으면 절감이 없거나 감소할 수 있습니다. 공식 활동일지·정산서 자동 생성은 현재 구현 범위가 아닙니다.
- 질문 180건은 콘텐츠 180문항과 별도 발생량 가정입니다. 답변 작성·상담 시간은 제외합니다. 질문이 늘면 총 튜터 업무는 증가할 수 있습니다.
- 기존에 단일 기록·공통 교재를 사용하는 기관은 출발점이 다릅니다. 90% 제작 건수 감소도 기관들이 동일 범위를 각각 새로 집필한다는 가정에 한합니다.
- 각 업무의 비율을 합산하거나 평균 내어 전체 운영·예산 절감률로 쓰지 않습니다. 중앙과 현장의 중복 집계 여부를 확인해야 합니다.
- 기관 간 공동 매칭·실제 전국 데이터 수집은 미구현입니다. 현장 공동 운영은 서버 인증·권한·동기화·동의·교과 검수·알림을 먼저 연결한 뒤 검증합니다.
