# 포근동행 · 15분 발표

[발표 HTML 열기](포근동행-15분-발표.html)

**21장 · 총 15분**, 출처·계산·외부 연구 부록 5장. 질의응답은 별도입니다. 요청한 소개 → 문제 현황 → 해결방식·유사 프로그램·차별점 → 네 역할의 흐름 → 마무리 순서를 따릅니다.

7번 장에서는 **전국 각지의 멘토링을 하나의 플랫폼에서 운영하는 구상**을 도식으로 설명합니다. 소개·역할별 운영·중앙기관·마무리와 발표 대본에도 연결했습니다. 지역 기관은 현장 매칭과 운영을 맡고 중앙은 공통 자료와 전국 운영 현황을 관리하는 구조입니다.

## 발표하기

1. `포근동행-15분-발표.html`을 Chrome 또는 Edge에서 엽니다. 초기 준비에 약 3초가 걸립니다.
2. **← / →** 또는 **Space**로 이동합니다. 화면 하단 탐색 버튼과 모바일 좌우 스와이프도 지원합니다.
3. **P** 또는 하단 발표 아이콘을 누르면 별도 청중 창과 발표자 노트가 열립니다. 발표자는 원래 창에서 대본과 경과 시간을 보며 진행합니다. 팝업을 차단했다면 이 파일의 팝업을 허용합니다.
4. **F** 또는 하단 전체화면 아이콘으로 확대합니다.
5. 마지막 장의 **출처·통계 기준**에서 참고자료 부록을 열 수 있습니다. 부록의 복귀 버튼으로 본편으로 돌아옵니다.

발표자 노트는 직접 고칠 수 있으며 같은 브라우저에 저장됩니다. 전체 대본은 [발표대본.md](발표대본.md)에도 있습니다. 화면 공유에서는 **청중 창만** 공유합니다.

HTML 파일 하나에 이미지·QR·스타일·슬라이드 실행 코드가 포함되어 있어 설치와 인터넷 연결 없이 발표할 수 있습니다. 출처 사이트, QR 체험 및 실시간 프로토타입 시연에는 인터넷이 필요합니다.

## 이번 업데이트 · 운영효율·지자체 기여 반영

- **6번:** 2026년 서울런·동대문구·천안·김포의 실제 사업 구조로 교체했습니다. 대상·기간·목적의 차이와 서울런의 기존 매칭 표준화를 명시했습니다. 천안·김포는 공고상 운영 사례이며 현재 모집을 뜻하지 않습니다.
- **7번:** 중앙의 공통 교재와 지역 기관의 최종 배정·현장 지원 책임을 구체화했습니다. 기관 간 연계와 전국 확장은 향후 범위입니다.
- **17번:** 중앙 교재 구성·검토 36→27시간(25%), 튜터 준비 회당 25→15분(360회에서 60시간), 기록 회당 10→6분(360회에서 24시간)의 조건부 계산을 보여 줍니다. 전부 실측이 없는 가정입니다. 전체 절감률로 합산하지 않습니다.
- **18번:** 공통 교재 재사용, 복습·질문과 다음 지도 연결, 운영 후속 지원의 세 기여를 설명합니다. 첫 적용 후보는 초5 수학·영어 기관 3~5곳입니다.
- **19–20번:** 서버·권한·동기화 연결 후 2주 기준선, 6~8주 파일럿, 검증 후 18주 확대 검토 순서로 바꿨습니다. 준비·검토·배정 시간과 오류·재작업, 복습·질문 응답을 함께 측정합니다.
- **부록 5장:** R1 통계 출처, R2 중앙 25%와 기관 포함 5.8%의 분모, R3 제작 건수·매칭·질문 계산, R4 지역 사례 출처, R5 외부 튜터링 연구입니다. 90%는 공통 원고 제작 건수입니다. 0.288 표준편차와 +4개월은 포근동행의 성과가 아닌 외부 연구 결과입니다.
- 발표대본·발표자 노트·근거 문서를 함께 갱신했습니다. 이번 버전은 별도의 노트 저장 키(`v3-operations`)를 사용하므로 이전 저장 노트가 새 대본을 가리지 않습니다.

## 16번 장 · 60초 시연 준비

미리 [공개 프로토타입](https://pogeun-donghaeng-demo.svbrbmssyf.chatgpt.site)을 다른 탭에서 열고, **가입 없이 예시 화면 체험하기 → 학생**으로 들어갑니다. 한 브라우저에서 **이지우 학생 → 김민서 튜터 → 이지우 학생**으로 역할을 바꿉니다. 관객의 휴대폰과 발표 노트북은 기록이 공유되지 않습니다.

- 학생: 수학 복습 → **여기서 막혔어요** → 질문 보내기.
- 질문 예시: `분모를 왜 같게 해야 하나요?`
- 튜터: 질문함 → 새 질문 확인 → 답변 보내기.
- 답변 예시: `같은 크기의 조각으로 바꿔 분자의 수를 비교하려고 분모를 같게 하는 거예요.`
- 학생: 답변 확인 → **이해했어요** → 발표자료 복귀.

질문·답변 문장을 붙여넣을 수 있게 준비하고 사전에 한 번 연습합니다. 연결이 불안정하면 16번 장의 흐름을 설명하고 넘어갑니다. 실제 개인정보나 서류는 입력하지 않습니다.

## 편집용 파일

- `scripts/build_deck.py`: 슬라이드 문장·대본·시간·스타일 원본. 실행하면 HTML과 대본을 갱신합니다.
- `manifest.json`: 본편·부록 순서와 발표 노트.
- `assets/`: 사용한 실제 배포 화면과 출처 기록.
- `composition/index.html`: 독립 HTML 발표의 본문. 이 파일만 직접 여는 대신 루트 발표 HTML을 사용합니다.

실행에는 HyperFrames 0.8.54의 공유 슬라이드 탐색·발표자 컴포넌트와 GSAP를 파일 안에 포함했습니다. 독립 파일 실행 시 원격 런타임 주입을 건너뛰는 명시적 어댑터를 빌드에 적용했습니다. 발표자 노트 저장과 청중 창 동기화는 공유 컴포넌트 동작을 사용합니다. 선형 MP4 내보내기용 프로젝트는 아닙니다.

## 이번 버전 검증

`python3 scripts/build_deck.py`로 독립 HTML·본문·manifest·대본을 생성합니다. `node scripts/check_deck.cjs`는 격리된 Chrome에서 오프라인 실행, 본편·부록 탐색, 발표자 노트·청중 동기화, 모든 장의 화면 범위·푸터 겹침을 확인하고 `qa/`에 결과와 스크린샷을 저장합니다. 실제 외부 링크와 QR의 목적지는 온라인입니다.

기존 독립 HTML 어댑터의 root 타임라인과 내장 GSAP의 `Math.random`·`Date.now`를 HyperFrames 0.8.54의 정적 검사기가 지적하므로 CLI `check`는 통과로 표시하지 않았습니다. 선형 영상 렌더용 프로젝트가 아니며, 발표 파일의 실제 브라우저 동작과 26개 장의 레이아웃은 별도 검사합니다.
